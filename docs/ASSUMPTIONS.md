# Assumptions and verification limits

These are explicit local policies, not claims about GRA's production behavior. The authoritative contract is [Postman v8.2](https://documenter.getpostman.com/view/29809098/2sBXVeGCzK). Official rate sources are linked in TAX-RULES.md. Each unresolved implementation point is marked `// ASSUMPTION:` beside the relevant code or isolated behind a named schema, policy or constant.

## Verified differences that are not guesses

- Currencies GHS, USD, EUR and GBP are explicitly listed in the tag table. The GHS playground restriction is a product choice.
- `REFUND_CANCELATION` and `PURCHASE_RETURN_CANCELATION` follow actual cancellation requests. The table uses a different spelling.
- `statment_of_account` follows the actual URL, including its typo.
- `ysdcmrctim` follows actual response bodies; the table uses `ysdcmrctime`.
- The TIN lookup path exists in `response.originalRequest.url` even though the top-level request URL is blank.
- Credit note is the only note request enum supplied. No debit note was invented.
- Seller metadata and customer phone stay local because the invoice payload has no fields for them.
- EXM combines zero-rated and exempt items in the source. The SDK cannot preserve a distinction absent from the wire contract.

A successful mock interaction establishes agreement with these local policies. Real credentials still require GRA onboarding, sandbox contract checks and independent tax review. Runtime and deployment checks actually performed are recorded in VERIFICATION.md.
